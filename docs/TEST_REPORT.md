# Отчёт end-to-end проверки

Проверка выполнена не мысленно, а **реальным прогоном в браузере**: Google Chrome
(headless, Playwright) управлял интерфейсом Kadra мышью и клавиатурой — те же
действия, что выполнил бы пользователь. Результаты экспорта проверены `ffprobe`,
кадр экспорта сравнён с кадром превью (PSNR). Тот же сценарий проходит во
встроенном Chromium Playwright (используется в CI).

Тестовые медиа (`tests/e2e/make_media.py`): `clip1.mp4` (H.264+AAC, 1920×1080, 30 к/с, 4 с),
`clip2.webm` (VP9+Opus, 1280×720, 25 к/с, 3 с), `clip3.mov` (H.264+AAC, QuickTime, 1280×720, 3 с),
`music.mp3` (44,1 кГц, 5 с), `title.png` (1920×1080).

## Синхронизация с сервером (`tests/e2e/cloud_e2e.py`)

Сервер FastAPI запускается локально; браузер A регистрируется, импортирует 2 файла,
собирает таймлайн и сохраняет проект на сервер (медиа загружаются с дедупликацией
по SHA-256). Браузер B с пустым IndexedDB входит в тот же аккаунт и открывает проект:
3 клипа на месте, оба файла скачаны (2 752 391 и 81 128 байт) — **пройдено**.

## API сервера (`server/tests/test_api.py`)

6 тестов pytest — **пройдено**: регистрация/вход/токены, CRUD проектов, загрузка
ассетов с дедупликацией, скачивание целиком и диапазоном (Range → 206), изоляция
пользователей, лимит размера (413), отключение регистрации, CORS preflight.

## Как воспроизвести

```bash
python tests/e2e/make_media.py /tmp/kadra-media
cd tests/e2e && python run_e2e.py /tmp/kadra-media /tmp/kadra-out
python cloud_e2e.py /tmp/kadra-media
cd ../../server && pytest -q
```

Скриншоты и экспортированные файлы сохраняются в каталог вывода (`/tmp/kadra-out`).
